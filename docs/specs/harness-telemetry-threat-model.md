# Harness telemetry and private-evidence threat model

**Plan:** `task_6304`, brief `memory_400`, epic `epic_133`
**State:** documentation and test plan; no new access-control implementation or viewer
**Review scope:** repository code and docs at the current `main` revision. This is not a penetration test or a claim about a live installation.

This model governs evidence used by harness metrics, dashboards, reports, attestations and optional judgments. Read it with `docs/specs/harness-metric-contracts.md`, which owns metric identity, evidence classes and availability semantics. This document does not authorize new collection, change retention or credentials, or make task-success claims.

## Trust roles

| Role | What it can establish | What it cannot establish by itself |
| --- | --- | --- |
| **Source / producer** (OpenCode, a plugin, Langfuse, a test runner) | That a particular version emitted or stored particular fields, subject to its coverage and integrity limits. | That a task was accepted, a check was independent, a run was complete, or a reported label is truthful. Source names, IDs and metadata may be attacker-controlled or sensitive. |
| **Subject** (location, session, run, task, agent) | The entity named by an exact source identity or explicit binding. | That similarly named entities from different sources, projects or locations are the same entity. A prompt turn, session busy period and task are not interchangeable. |
| **Collector / transformer** (plugin, report, metric producer) | The allowlisted fields it received and the transformation it applied, when version and scope are recorded. | Completeness beyond its source, correct joins without explicit identities, or independent task acceptance. A bug or compromised process can alter evidence. |
| **Attestor** (human, agent or automation) | That a claim was explicitly supplied with that declared provenance and timestamp. | Independent verification. Agent-declared completion or checks, and even a human attestation, remain claims unless separately verified against authorized evidence. |
| **Assessor** (human or optional local model) | A versioned judgment over the evidence explicitly selected for assessment. | An observed fact, ground truth, root cause or success outcome. LLM judgments remain fallible and susceptible to instructions embedded in evidence. |
| **Storage / operator** (Langfuse project, local host, Docker/Tailscale administrator) | Access permitted by the configured account, project key, filesystem permissions and network policy. | Isolation from local administrators, backups, other enabled exporters or a misconfigured shared project. Loopback and “local” are not equivalent to user isolation. |

Authenticated telemetry authenticates access to a configured Langfuse project; it does not authenticate the meaning or completeness of every event. An error-free trace, successful busy-period drain, agent-declared check, or selected LLM label is not independent acceptance evidence. Keep `observed`, `derived`, `attested`, `judged` and `unavailable` distinct.

## Current data paths and boundaries

| Path | Implemented boundary | Residual risk / limitation |
| --- | --- | --- |
| **Global OpenCode tracing** | After installation, the default-on adapter reads one owner-only mode-600 global configuration and passes credentials only to its integrity-checked plugin instance. The documented opt-out is `AI_OBSERVATORY_DISABLED=1` on a new standalone server. | It applies across OpenCode project locations and sends rich trace content—including prompts/context, reasoning, model output and tool inputs/outputs—to its one configured destination. Per-location in-memory state handling is not storage isolation. A shared Langfuse project/key can aggregate locations; no repository or agent tenant boundary is promised. Other exporters remain independent. |
| **Project-specific OpenCode launcher** | Credentials are stored in owner-only files named from the absolute project directory; the launcher checks the matching project configuration and disables the global adapter in that launched process. | A path-specific credential file is not a separate Langfuse project. If the same project key is supplied, data shares that project's authorization and storage boundary. Other plugins/exporters remain out of scope. |
| **Structural runtime events** | The optional plugin emits an explicit structural allowlist rather than prompt/tool text; capture is separate and can be disabled independently. | Best effort, with possible loss and no guaranteed replay. Busy-period events can span multiple prompts. Some existing event IDs are deterministic legacy digests and are not project-keyed; hashing does not make an identifier anonymous or authorize a join. |
| **Native dashboards** | Provisioning and API calls use the configured project key. Managed dashboard state records a project ID and refuses reuse when the current project differs. Browser access remains under Langfuse's own account/project authorization. | Project-wide tool charts can include other integrations. The ownership-state check protects managed-resource reuse; it is not a guarantee that observations are repository- or agent-isolated inside one Langfuse project. Dashboard URLs and chart contents can still be sensitive. |
| **Structural report** | Uses the current project credentials and a bounded time window (default seven days, maximum 90 days); it fails on scan limits instead of silently truncating. Default cap is 10,000 observations, configurable up to 100,000. Requests selected basic/model/usage/metrics fields, does not request `io` or metadata, discards status messages, emits JSON to stdout, and writes no report file. Session filtering and trace/session identifiers are explicit options. | Names, counts, times and IDs can still identify people or work. Project-wide observations may include other emitters; filters do not create a repository/task join. Shell redirection, terminal capture, logs or copy/paste can persist stdout outside the tool's control. JSON output is not HTML- or spreadsheet-safe by virtue of being JSON. |
| **Task attestations** | Reads only the operator-selected file, rejects symlinks and unsafe ownership/mode, enforces exact fields and size/count bounds, and never discovers, uploads or writes evidence files. | The contents and bindings are explicit claims, not verified facts. Optional identifier output can be sensitive. The file and report remain the operator's responsibility. |
| **Optional local-model evaluator** | Requires one explicitly selected private case and `--allow-sensitive`; bounds fields and size, checks for a locally downloaded model and local routing before each call, disables proxies/redirects, validates a strict label schema, and prints labels rather than evidence text. | Selected text is sent to the local LM Studio API. “Local” does not exclude host users, administrators, Docker workloads or changed routing; prompt injection can still affect the model. It does not create Langfuse scores or prove outcomes. |
| **Public documentation site** | `site/build.mjs` copies/renders only an explicit allowlist (currently 11 output files), rejects symlinked inputs and unexpected output paths, escapes generated HTML/attributes, and sets CSP `script-src 'none'`. It contains documentation, not runtime reports or Langfuse keys. | The site is public. A future page, data file, client script or viewer changes this boundary and needs a fresh allowlist, privacy and injection review. The threat-model spec itself is not in the site source allowlist. |

### Isolation and authorization rules

1. Treat a **Langfuse project plus its membership and project-scoped API key** as the current server-side authorization boundary. For repository, customer or agent separation requirements, use separate Langfuse projects and separately controlled keys; do not claim isolation merely because paths, sessions, dashboard state or UI filters differ.
2. The global adapter deliberately serves multiple OpenCode locations with one global configuration. If those locations use one destination project, they are pooled there. Do not infer a repository, location or agent dimension unless a source explicitly supplies and validates it. The project-specific launcher narrows plugin configuration by local path but does not itself create a storage tenant.
3. Scope every relationship by source namespace/version and the applicable project boundary. Use exact source-issued opaque IDs or explicit authored bindings. Never join by display name, timestamp proximity, path, prompt similarity or a digest of private content. Legacy deterministic hashes are not pseudonymization proof; unsalted hashes of prompts, tool arguments/results, paths or memory are prohibited as a privacy substitute.
4. Tool/model names, IDs, labels, environment values and metadata are untrusted strings and may contain sensitive or hostile content. Treat them as display data, not identity or instructions. Validate schema and size; encode for the final output context. JSON serialization alone does not make values safe to embed in HTML, templates, URLs or spreadsheets.
5. An API key must remain in the private CLI/server configuration and authenticated Langfuse API path. Never embed public or secret project keys in a browser bundle, static page, URL, generated report, issue, or client-side viewer. A new viewer is out of scope until its authentication, project authorization, output encoding, CSP and isolation capabilities have been reviewed.

## Data minimization and export lifecycle

- Do not add raw prompts, reasoning, commands, tool arguments/results, memory, paths, error text, secrets or unrestricted metadata to metric records. The existing tracing integration already captures sensitive content; this rule prevents expanding that capture into new metric/report surfaces and does not claim the existing traces are redacted.
- Default aggregates and structural reports are not automatically safe to share. Keep optional identifiers and selected evidence off by default; choose a bounded window/session and smallest required fields. Do not treat missing source evidence as zero.
- The report currently prints to stdout and creates no file. If an operator saves output, use a restrictive `umask`, private location, controlled access and an explicit deletion/retention decision. Consider shell history, terminal recording, CI logs, scheduler output, backups and copy/paste destinations.
- Task-evidence files are read only when their path is explicitly selected. Evaluator evidence is a separate explicit disclosure to local LM Studio. Neither path discovers other files, writes attestations/scores, backfills history or schedules itself.
- No CSV/spreadsheet export path or custom browser evidence viewer was found. Do not imply either is protected today. If CSV is introduced, defend against formula execution (including leading whitespace/control characters before `=`, `+`, `-` or `@`) and test the exact spreadsheet-facing export; CSV quoting alone is insufficient. If a viewer is introduced, perform context-specific encoding and authorization checks before release.
- Existing Langfuse retention is not automatically enforced by this repository. Raw-volume backups are unencrypted snapshots. Apply the existing access, encryption, retention and restore guidance in `docs/security.md`; this task changes none of it.

## Source limitations and decision provenance

- OpenCode's default event bus is not a complete/replayable history source. Optional lifecycle capture is best effort; a missing event is not proof of no event.
- A terminal runtime event may represent a session busy period covering coalesced prompts; it cannot establish the outcome of one prompt or task.
- Native Langfuse tool views can include non-OpenCode emitters, and native charts do not generally provide arbitrary parent/child joins. Do not promote project-wide tool counts to OpenCode-only measurements.
- No universal repository/task-to-turn binding, independently verified task acceptance, satisfaction, root cause, or production-quality LLM judge is present. A selected attestation or judgment does not fill those gaps.
- Record source, producer/API version, transform version, exact scope/filters, time window, computation time, coverage and exclusions for every derived result. Judgments additionally need assessor/model, rubric version, selected-evidence scope and an explicit `judged` class. Keep unavailable reasons and decision provenance visible.
